================================================================================
  IMPACT — SKILL TREE TAG REFERENCE
  Generated from: ImpactTree_NodeData.xlsx (NodeDataTable workflow)
================================================================================
  Each node data asset needs:
    NodeTag       →  SkillTree.Impact.GroupName.#   (node identity)
    Effect tags   →  SkillPassive.Impact.EffectName (on each
                     FFP_NodeEffect_SkillPassive in the Effects array)

  The passive tag is written into PlayerState's SkillPassiveValues accumulator
  on commit, and read back at cast time via AFP_PlayerState::GetSkillPassiveValue().

  Every SkillPassive tag in this tree lives under the "SkillPassive.Impact"
  root and every node's flavour text ends in "...with Impact" / "...with
  Initial Impact" / "...with Secondary Impacts" — deliberately, so a bonus
  from this tree can never leak into an unrelated skill. Wording convention:
    Increased / Reduced  — the common, additive percent bucket (stacks
                            linearly with other Increased/Reduced sources).
    More / Less          — the rare, multiplicative bucket. Used sparingly
                            (only on Major/Mastery nodes here) since it's
                            stronger than Increased/Reduced for the same %.

  71 nodes total. Distribution favours Initial Impact first, whole-skill
  second, Secondary Impacts deliberately rarest (per design brief):
    Initial Impact only : 29 nodes (6 core + 23 stat)
    Whole skill          : 30 nodes (5 core + 25 stat)
    Secondary Impacts only: 16 nodes (12 core + 4 stat, rarest by design)

    SkillPassive.Impact.IncreasedAgainstBruised
    SkillPassive.Impact.SecondaryCritChance
    SkillPassive.Impact.SecondaryPhysicalDamage

  Reasons these aren't live yet, briefly:
    - Initial*/Secondary* scoped Crit/Physical/Area variants need the same
      kind of dedicated SetByCaller bucket IncreasedPhysicalDamage just got,
      but split by "did this hit come from the initial swing or a chained
      detonation" — UFP_GA_Impact would need to stamp a different spec per
      hit rather than sharing one generic AssignSkillPassiveBonuses pass.
    - Bruised buildup/duration needs an Impact-scoped debuff pathway, the
      same way LightningCoil's Corroded buildup works (send a
      GameplayEvent.Debuff.Buildup.Bruised to the target with an
      accumulated magnitude; a UFP_GA_BruisedPassive-equivalent on the
      enemy intercepts it).
    - ArmourPenetration / LifeOnHit need their own SetByCaller buckets in
      ExecCalc_Damage.cpp — not yet requested/added.
    - IncreasedMeleeDamage/AreaDamage deliberately do NOT reuse the global
      Damage.Increased.Melee/AoE attributes — those are shared category
      buckets any melee/AoE skill can already draw from (e.g. Might tree
      nodes), and stamping Impact's spec with SkillTagMod.Melee/.AoE (see
      below) already lets it benefit from them for free. A per-skill
      "SkillPassive.Impact.IncreasedMeleeDamage" bucket would need new,
      dedicated ExecCalc plumbing to stay Impact-exclusive.

  CORE MECHANIC GROUPS (23 nodes)
--------------------------------------------------------------------------------
  Initial Area of Effect  (5, Minor, start)      "10% Area of Effect to Initial Impact."
    SkillPassive.Impact.InitialAreaOfEffect, 0.10/node. UFP_GA_Impact applies
    sqrt(1+sum) to the initial AoE radius (area-preserving circle scaling,
    same convention as the base class's own GetEffectiveSphereRadius).
    Gates Initial Radius (Major).

  Initial Radius  (1, Major)                     "+3 Radius to Initial Impact."
    SkillPassive.Impact.InitialRadius, magnitude 3.0 — stored in METRES,
    UFP_GA_Impact multiplies by 100 before adding to BaseInitialRadius (cm).
    Gates Secondary Area of Effect.

  Secondary Area of Effect  (5, Minor)           "8% Area of Effect to Secondary Impacts."
    SkillPassive.Impact.SecondaryAreaOfEffect, 0.08/node, same sqrt scaling
    applied to the secondary/chained AoE radius. .3 gates Chain Depth.1.
    Gates Secondary Radius (Major).

  Secondary Radius  (1, Major)                   "+1 Radius to Secondary Impacts."
    SkillPassive.Impact.SecondaryRadius, magnitude 1.0 (METRES, x100 in code).

  Secondary/Chain Damage  (6, Minor, start)      "15% Increased Damage with Secondary Impacts."
    SkillPassive.Impact.SecondaryDamageMultiplier, 0.15/node — bumped up
    from the original 0.08 per the redesign (secondary damage is meant to
    hit harder per point invested than a flat "Increased Damage" node).
    .4 gates both Hasty and Patient Detonation. .6 gates Secondary Crit Chance.

  Chain Depth  (2, Major)                        "+1 to Chained Secondary Impacts."
    SkillPassive.Impact.MaxChainDepth, 1.0/node. .1 gates .2 and the
    Mastery capstone.

  Hasty Detonation  (1, Major, gated by SecondaryDamage.4)
    "20% Reduced Damage with Secondary Impacts.\n30% Reduced Secondary Impact Chain Delay."
    SecondaryDamageMultiplier -0.20, ChainDelayModifier -0.30.

  Patient Detonation  (1, Major, gated by SecondaryDamage.4)
    "20% Increased Damage with Secondary Impacts.\n30% Increased Secondary Impact Chain Delay."
    SecondaryDamageMultiplier +0.20, ChainDelayModifier +0.30.
    NOTE: the exact wording/sign pairing here (Hasty = less delay AND less
    damage; Patient = more delay AND more damage) was inferred from the
    original -30%/-20% and +30%/+20% design — flag if the intent was
    actually reversed.

  Mastery — Chain Reaction  (1, gated by ChainDepth.2)
    "+1 Chained Secondary Impacts.\n10% More Impact Damage."
    MaxChainDepth +1.0, MoreDamage +0.10 (live, generic leaf).

--------------------------------------------------------------------------------
  TAGS REFERENCED BUT NOT PART OF THIS TREE
--------------------------------------------------------------------------------
  SkillTagMod.Chain / .Duration / .Melee / .AoE / .MeleeWeapon / .Mace —
  stamped onto Impact's damage GameplayEffectSpec via UFP_SkillLibrary's
  FFP_AbilityEntry.SkillModifierTags (editor data, not a skill-tree node).
  Lets *external* sources (gear, Might's melee/AoE nodes, other passive
  trees) grant generic bonuses that also apply to Impact. Add these to
  Impact's SkillLibrary entry when it's configured in the editor.

  Duration.Skill — the shared/global skill-duration attribute
  (UFP_AttributeSet::SkillDuration). This tree does not spend a node on it
  directly (an earlier draft did — removed per design feedback: increased
  duration alone has no upside without a paired damage trade-off, and that
  trade-off already exists via Hasty/Patient Detonation). Other trees or
  gear can still feed Duration.Skill via a Stat Mod node; UFP_GA_Impact
  already reads it in GetEffectiveChainDelay().
